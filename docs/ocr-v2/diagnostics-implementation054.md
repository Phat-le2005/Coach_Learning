# OCR diagnostics 05.4

This is an isolated local QA tool for separating scope selection (H1), model/preprocessing (H2), and decoding/repair/selection (H3). It does not change the student OCR path, segmentation, models, evaluator, database, or submission adapter.

## Run

From `frontend`:

```powershell
npm run test:ocr-diagnostics
npm run typecheck
npm run build
```

From the repository root, with Chrome installed:

```powershell
node tools/ocr-fixtures/run_ocr_diagnostics.cjs
```

The default input is `.tmp/tri-ocr-native/integral_case_01.json`. Outputs go to `.tmp/tri-ocr-diagnostics/`. The runner starts the actual Next.js dev application on free port 3004 and stops only its own server. No account, QA database, or backend is required. It runs real bundled ONNX/WASM, not mocks. Missing input produces `BLOCKED_MISSING_REAL_INK`. Missing independent labels produces `BLOCKED_MISSING_HUMAN_GROUND_TRUTH`, with automatic-scope smoke results but no oracle accuracy.

```powershell
node tools/ocr-fixtures/run_ocr_diagnostics.cjs .tmp/my-capture.json --annotation .tmp/my-annotation.json --e2 --output .tmp/diagnostics-my-sample
```

`--profile LEGACY_REGIONS`, `--profile IR_ATOMIC`, or default `both` select the current automatic paths. They are reported separately, not pooled or silently improved. `LEGACY_REGIONS` replays the current `segmentPageInk_v2()`; `IR_ATOMIC` uses the current structural/integral proposals and IR construction, and submits only atomic MATH. Containers/non-math are recorded as not sent. Captured segmentation is never treated as ground truth.

## Add real ink and independent labels

1. In development MathCanvas, write and export using **Xuất nét và phân vùng (QA)**. Keep the capture unchanged in a gitignored directory.
2. Open `/ocr-diagnostics` on the dev frontend, also linked from the existing shadow QA panel. Import **Capture JSON**. No upload API is called.
3. Before running OCR, click the numbered pen strokes belonging to one complete expression, enter its independently read LaTeX, and click **Thêm nhóm nhãn**. Repeat for other expressions. Use TEXT/UNKNOWN for unsupported or ambiguous content. A mistaken group can be removed before verification.
4. Check the independent-human-review checkbox and download the verified annotation. This is a declaration by the human annotator; software cannot certify independent authorship. Do not use predictions to fill labels. Annotation is locked after viewing OCR or verification. Re-importing cannot make an OCR-derived label independent.
5. Run A/B in the UI and export results, or use the CLI with `--annotation`. For complex relations, edit the annotation JSON before running. Add optional pseudonymous `writerId` only when known; absence is reported as NOT_AVAILABLE.

Reuses `OcrGroundTruthV1`, with optional recognition metadata and enriched `expectedGroups`. A template without guesses is generated by the runner. Example shape (illustrative IDs only):

```json
{
  "schemaVersion": 1,
  "sampleId": "my-capture",
  "captureFile": "my-capture.json",
  "captureSha256": "SHA256_OF_UNCHANGED_CAPTURE_BYTES",
  "annotationStatus": "HUMAN_VERIFIED",
  "annotator": { "kind": "HUMAN", "id": "optional-pseudonym" },
  "labelSource": "HUMAN_INDEPENDENT_OF_OCR",
  "expectedGroups": [
    { "groupId": "expression-A", "strokeIds": ["actual-stroke-id"], "contentKind": "MATH", "latex": "independently transcribed LaTeX" }
  ]
}
```

`childGroupIds` optionally expresses hierarchy, with the existing `kind` field carrying SYSTEM/ALTERNATIVES/FRACTION. Children must exist and reference a subset of parent ink. Cycles, multiple parents, duplicate references/IDs, unrelated ownership overlap, unknown source IDs, and source-checksum mismatches are rejected. Missing annotation coverage is explicitly reported, not filled by OCR. TEXT/UNKNOWN/STRUCTURE scopes are retained but not sent to CoMER. A full fraction can be a MATH oracle scope even when the automatic IR path splits it into children; baseline A remains unchanged.

TEXT groups retain literal transcription in optional `text`; MATH uses `latex`. Neither TEXT nor its transcription is passed to CoMER or counted as math recognition accuracy.

## Observability and maintenance

`ocr-model-diagnostics.ts` imports the same vendored `ink-on/core.js` and preprocessing, creates its own engine instance, and temporarily wraps **that instance's** `beamDecode()` to copy its returned candidates. It returns the original candidates unchanged and restores the method in `finally`. It does not monkey-patch the prototype, change beam search, re-rank candidates, edit the vendor bundle, or edit ONNX weights. The existing `handwritten-ocr.ts` is unchanged.

The vendored runtime is ink-on 0.1.0, with its TypeScript source embedded in the accompanying source map (`preprocessing.ts`, `tokenizer.ts`, `latex-repair.ts`, `inference.ts`). The observation adapter relies on JS methods compiled from TypeScript `private`; it is pinned to this runtime and its checksum. On vendor upgrades, re-audit method names, return shape, scoring, masks, and selected-output parity. No vendor rebuild or undocumented bundle patch is introduced.

Available per completed inference:

- Actual model buffer, vocab, and runtime SHA-256; config `expression`, WASM, beam width 3, max decode steps 50 (current vendor default), repeat limit 3.
- Returned token IDs and decoded token strings **before** `repairLatex`, repaired LaTeX for each beam, final vendor-selected LaTeX, and the unchanged frontend wrapper's accept/reject boundary.
- Up to three returned beam candidates, natural-log `logProb`, rank, and matching selected candidate ranks. The vendor normalizes by sequence length **including SOS**: `logProb / max(returnedIds.length + 1, 1)`. The score may include an EOS/repeat transition that is not retained in the token IDs. Completed candidates are preferred by the vendor. Scores are not calibrated confidence and are not comparable as probabilities across scopes.
- KaTeX validity of raw/repaired candidates, labeled as a separate diagnostic. The vendor's selection uses its own lightweight structural check; that internal check is not exported, so its outcome is NOT_AVAILABLE. Neither check establishes mathematical correctness.
- Vendor encoder/decoder/total timing, adapter preprocessing/action timing. Vendor `decoderMs` includes beam search, repair/selection and disposal overhead; it is not decoder-session time alone. Initial action time can include model loading. Serialized parity calls are extra inference work and are reported separately.
- Actual preprocessed tensor grayscale PNG plus tensor/mask hashes and dimensions. This preview is derived from the float tensor actually sent to the encoder, not a substitute renderer.

NOT_AVAILABLE: per-beam EOS/max-length/repeat stop reason (discarded by vendor), complete decoder event stream, internal structural-check result, calibrated confidence, and attention. Returned IDs omit SOS, EOS, and discarded repeat terminators; “raw” here means pre-LaTeX-repair decoding, not a full decoder-event trace. Raw logits are not retained. The existing IR's `rawRecognition` is the legacy wrapper's **already repaired/selected** output; do not confuse it with these new pre-repair diagnostics.

## Comparison and interpretation

Oracle ink is selected by exact annotated IDs in original source order. The label string never enters model prediction. Both arms use the same recognition callback, model hashes, config and default preprocessing. Alignment uses stroke sets, not array index. Each automatic scope records intersecting/missing/extra IDs against each labeled MATH group. Non-exact or ambiguous matches are segmentation/alignment errors and are excluded from recognition comparison. Containers are not emitted as automatic predictions merely to make alignment pass.

Recognition comparison uses conservative LaTeX lexical token edit distance/exactness and a small set of structural-marker count differences. It preserves case, command boundaries, wrong math and raw text; it does not perform mathematical equivalence or AST reconstruction. Oracle abstentions count as recognition failures; infrastructure errors and their denominator exclusion are separately reported. Report per-profile/per-group results and label provenance; tiny samples do not establish accuracy/generalization.

E2 optionally applies **only** width multipliers 0.75 and 1.25 to model-space line width, alongside default 1.0, on independently labeled oracle scopes. Vendor rendering clamps effective width to at least 2 pixels; effective values are recorded. Padding 16, resampling interval 3, smoothing, content target height 128, canvas height 256, width alignment 64/minimum 128/maximum 1024 and normalization are unchanged. Padding/scale/anti-alias controls are not exposed by this runtime; they are NOT_AVAILABLE rather than replaced by another rasterizer. E2 does not choose a winner or change defaults. Without verified human labels, E2 remains blocked.

Artifacts: `manifest.json`, `results.json`, `summary.json`, `REPORT.md`, `annotation-template.json`, `browser_network.json`, screenshots, and `preprocessing/*.png`. The manifest records source-file hashes as well as Git HEAD and dirty state, because this implementation is intentionally local/uncommitted. Results distinguish application API mutations from Next.js dev-tool stack-frame requests, both recorded. Diagnostics is disabled in production and its page returns 404.

For the existing native integral, obtain a human scope/label before attributing H1 versus H2. Read raw versus repaired candidates to locate H3 effects on each sample; absence of repair changes on one sample does not rule out H3 elsewhere. No new recognition architecture is selected by this tooling.
